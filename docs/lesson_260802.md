### 0-1. 전체 과정의 목표와 학습 경로

#### 주제

ROS 2와 Isaac Sim을 이용해 가상 로봇의 1자유도 관절을 움직이는 전체 경로를
확인한다.

#### 내용 설명

최종 목표는 **ROS 2에서 목표 각도를 보내 Isaac Sim 속 회전 관절 하나를
움직이는 것**이다.

**1자유도(1-DOF)**는 독립적으로 움직일 수 있는 방향이 하나라는 뜻이다. 문에
달린 경첩처럼 한 축을 중심으로만 회전하는 관절이 대표적인 예다.

전체 과정은 다음 순서로 진행한다.

1. 컴퓨터와 소프트웨어 환경을 확인한다.
2. ROS 2 노드와 토픽으로 메시지를 주고받는다.
3. Python으로 ROS 2 노드를 직접 작성한다.
4. URDF로 몸체 두 개와 회전 관절 하나를 표현한다.
5. Isaac Sim에서 관절을 직접 움직인다.
6. ROS 2 Bridge로 ROS 2와 Isaac Sim을 연결한다.
7. ROS 2에서 보낸 목표 각도로 관절을 움직인다.

실습 상태: 학습 경로 결정 완료

### 0-2. 학습 도구의 역할

#### 주제

ROS 2, URDF, Omniverse와 Isaac Sim이 각각 무엇을 담당하는지 구분한다.

#### 내용 설명

- **ROS 2(Robot Operating System 2)**: 로봇 프로그램을 기능별로 나누고 서로
  통신하게 해 주는 도구 모음이다. 이름과 달리 Ubuntu를 대신하는 운영체제는 아니다.
- **URDF(Unified Robot Description Format)**: 로봇의 몸체인 `link`와 연결부인
  `joint`를 XML로 기록하는 로봇 설계도다.
- **Omniverse**: 3D 장면과 관련 도구를 연결하는 NVIDIA의 기반 기술이다.
- **Isaac Sim**: Omniverse 기술을 바탕으로 로봇, 센서와 물리 현상을
  시뮬레이션하는 애플리케이션이다.

| 목표 관절 각도를 다른 프로그램으로 전달 | ROS 2 |
| 몸체와 관절 구조를 설계 | URDF |
| 3D 장면의 기반 기술과 USD 데이터를 관리 | Omniverse |

### 1-2. ROS 2 Jazzy 설치 확인

#### 주제

ROS 2 실행 파일, 활성 배포판과 핵심 패키지의 설치 경로가 일치하는지 확인한다.

#### 내용 설명

ROS 2는 Jazzy, Humble 같은 **배포판(distribution)** 단위로 출시된다. 다음 세
결과가 모두 Jazzy를 가리키므로 ROS 2 Jazzy가 설치되어 있고 현재 터미널에도

| 확인 항목 | 실제 결과 | 의미 |
| --- | --- | --- |
| 실행 파일 | `/opt/ros/jazzy/bin/ros2` | `ros2` 명령이 설치됨 |
| `ROS_DISTRO` | `jazzy` | 현재 터미널이 Jazzy 환경을 사용 |
| `rclpy` 경로 | `/opt/ros/jazzy` | Python용 ROS 2 패키지도 설치됨 |

#### 예제 또는 실습

실습 상태: 완료

```bash
command -v ros2
echo "$ROS_DISTRO"
ros2 pkg prefix rclpy
```

실제 결과:

```text
/opt/ros/jazzy/bin/ros2
jazzy
/opt/ros/jazzy
```

성공 확인: 세 결과가 모두 Jazzy 설치 경로와 일치하면 된다.

### 1-3. Isaac Sim 버전 선택

#### 주제

Isaac Sim 4.5, 5.0과 6.0 계열을 운영체제, ROS 2, Python과 GPU 기준으로 비교한다.

#### 내용 설명

| --- | --- | --- | --- |
| 6.0 계열 | Ubuntu 24.04 + Jazzy, Python 3.12 계열 | RTX 4080, VRAM 16GB | 소프트웨어가 가장 잘 맞음. GPU 검사 필요 |

조건부 대안으로 검토한다.

### 2-1. 노드, 토픽과 메시지

#### 주제

ROS 2의 프로그램 단위와 데이터 통신 구조를 이해한다.

#### 내용 설명

- **노드(Node)**: 카메라 읽기나 관절 제어처럼 한 가지 역할을 맡은 프로그램 단위
- **토픽(Topic)**: 계속 발생하는 데이터를 전달하는 이름 있는 통신 채널
- **메시지(Message)**: 토픽으로 전달하는 데이터의 구조와 값
- **발행자(Publisher)**: 토픽에 메시지를 보내는 쪽
- **구독자(Subscriber)**: 토픽에서 메시지를 받는 쪽

```text
talker 노드  -- String 메시지 -->  /chatter 토픽  -->  listener 노드
  발행자                                               구독자
```

토픽은 데이터를 저장하는 파일이 아니라 실시간 통신 채널이다. 기본 설정에서는
구독자가 접속하기 전에 지나간 메시지를 다시 전달하지 않는다. 그래서 listener를
나중에 실행하면 1번이 아니라 현재 발행 중인 번호부터 받는다.

#### 예제 또는 실습

실습 상태: 개념 확인 완료

학교 방송에 비유하면 방송부는 발행자, 방송 채널은 토픽, 방송 내용은 메시지,
교실의 스피커는 구독자다.

성공 확인: `/chatter` 자체와 `Hello World: 18`이라는 값을 구분해 설명할 수
있으면 된다.

### 2-2. Talker와 Listener 통신

#### 주제

C++ talker와 Python listener 예제 노드를 실행해 `/chatter` 통신을 확인한다.

#### 내용 설명

`talker`는 약 1초마다 `std_msgs/msg/String` 메시지를 `/chatter`에 발행한다.
`listener`는 같은 토픽과 자료형을 구독해 받은 문자열을 출력한다. 두 프로그램이
각자 다른 터미널에서 실행돼도 ROS 2가 같은 토픽을 사용하는 노드를 찾아 연결한다.

#### 예제 또는 실습

실습 상태: 완료

첫 번째 터미널:

```bash
ros2 run demo_nodes_cpp talker
```

두 번째 터미널:

```bash
ros2 run demo_nodes_py listener
```

실제 출력의 핵심 부분:

```text
[talker]: Publishing: 'Hello World: 18'
[listener]: I heard: [Hello World: 18]
```

성공 확인: talker가 발행한 것과 같은 문자열과 번호가 listener에 표시되면 된다.
종료할 때는 각 터미널에서 `Ctrl+C`를 누른다.

### 2-3. ROS 그래프와 메시지 관찰

#### 주제

CLI로 실행 중인 노드, 토픽, 연결 수와 메시지 설계도를 확인한다.

#### 내용 설명

**ROS 그래프(ROS graph)**는 실행 중인 노드와 이들이 사용하는 토픽, 서비스,
액션 등의 연결 관계다. `/chatter [std_msgs/msg/String]`은 `/chatter`라는
토픽에서 `std_msgs` 패키지의 `String` 메시지 자료형을 사용한다는 뜻이다.

`std_msgs/msg/String`의 필드는 다음 하나다.

```text
string data
```

따라서 실제 메시지는 다음 구조로 보인다.

```yaml
data: 'Hello World: 30'
```

`std_msgs/msg/String`의 deprecated 주석은 학습 예제에서 사용할 수 없다는
오류가 아니다. 실제 로봇 기능에서는 용도가 분명한 사용자 정의 메시지를 만들라는
권고다.

#### 예제 또는 실습

실습 상태: 완료

```bash
# 실행 중인 노드
ros2 node list

# 토픽 이름과 메시지 자료형
ros2 topic list -t

# /chatter의 자료형과 발행자·구독자 수
ros2 topic info /chatter

# /chatter에서 흐르는 실제 메시지 값
ros2 topic echo /chatter

# String 메시지의 필드 설계도
ros2 interface show std_msgs/msg/String
```

실제 확인 결과:

```text
/listener
/talker

Type: std_msgs/msg/String
Publisher count: 1
Subscription count: 1
```

성공 확인: 노드 목록, 토픽 이름, 자료형과 실제 메시지 값을 각각 찾을 수 있으면 된다.

### 2-4. 로그 구분과 CLI 직접 발행

#### 주제

로그 한 줄을 구성 요소로 나누고 CLI를 발행자로 사용한다.

#### 내용 설명

다음 출력에서 `/chatter`로 전달된 값은 마지막 문자열뿐이다.

```text
[INFO] [1785612960.973238513] [listener]: I heard: [my first ROS 2 message]
```

| 출력 부분 | 의미 | 토픽으로 전달됐는가? |
| --- | --- | --- |
| `[INFO]` | 로그 중요도 | 아니요 |
| 긴 숫자 | 로그가 기록된 ROS 시간 | 아니요 |
| `[listener]` | 로그를 출력한 노드 이름 | 아니요 |
| `I heard:` | listener 코드가 붙인 설명 | 아니요 |
| `my first ROS 2 message` | 메시지의 `data` 값 | 예 |

`I heard: []`은 오류가 아니라 `data`가 빈 문자열인 메시지를 받은 결과다.

#### 예제 또는 실습

실습 상태: 완료

talker를 종료하고 listener는 실행한 상태에서 다음 명령을 실행했다.

```bash
ros2 topic pub --once /chatter std_msgs/msg/String \
  "{data: 'my first ROS 2 message'}"
```

실제 수신 결과:

```text
[listener]: I heard: [my first ROS 2 message]
```

성공 확인: CLI에 입력한 문자열이 listener에 그대로 표시되면 된다.

### 3-1. 워크스페이스와 colcon

#### 주제

직접 Python 노드를 만들기 전에 코드와 빌드 결과가 놓일 작업 공간을 준비한다.

#### 내용 설명

**워크스페이스(workspace)**는 여러 ROS 2 패키지와 빌드 결과를 모아두는 작업
공간이다. `colcon`은 워크스페이스 안의 패키지를 찾아 빌드하는 도구다.

```text
study_ros/
└── ros2_ws/
    ├── src/       # 직접 작성하거나 내려받은 패키지 원본
    ├── build/     # 빌드 중간 파일
    ├── install/   # 실행할 수 있도록 정리된 결과
    └── log/       # 빌드 과정의 로그
```

`src`는 먼저 만들고, `build`, `install`, `log`는 패키지를 만든 뒤
`colcon build`를 실행하면 생성된다.
