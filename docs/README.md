# ROS와 Isaac Sim 학습자료 안내

이 폴더는 수업에서 실제로 다룬 내용을 날짜별 교재로 정리하는 공간이다.
각 문서는 혼자 다시 읽고 실습해도 이해할 수 있도록 작성한다.

## 학습 카테고리

| 순서 | 카테고리 | 배우는 내용 |
| --- | --- | --- |
| 0 | 학습 안내와 프로젝트 관리 | 학습 계획, 저장소 구조, Git 기록 방법 |
| 1 | 설치와 환경 점검 | 운영체제, GPU, 드라이버, ROS 2, Isaac Sim 설치 |
| 2 | 터미널과 프로그래밍 기초 | Linux 명령, Git과 Python 기초 |
| 3 | ROS 2 기본 개념과 CLI | 워크스페이스, 패키지, 노드, 토픽, 서비스, 액션, 파라미터 |
| 4 | ROS 2 프로그래밍 | `rclpy`, publisher, subscriber, launch, 디버깅 |
| 5 | 로봇 모델링 | 좌표계, TF, link, joint, URDF, Xacro |
| 6 | 시뮬레이션 기초 | Omniverse, USD, Isaac Sim, Stage, Prim, 물리 엔진 |

한 수업에서 여러 카테고리를 다루었다면 하나의 날짜 문서 안에 여러 주제로
나누어 기록한다.

## 파일 이름 규칙

- 형식: `lesson_YYMMDD.md`
- 날짜 기준: Asia/Seoul
- 예시: 2026년 8월 2일은 `lesson_260802.md`
- 같은 날짜에는 기존 파일을 갱신하고, 날짜가 바뀌면 새 파일을 만든다.
- `lesson_260000.md`처럼 실제로 존재하지 않는 날짜는 사용하지 않는다.

## 장과 절의 번호 규칙

- 큰 학습 카테고리는 `## 0.`, `## 1.`, `## 2.` 형식의 **장**으로 만든다.
- 한 장 안의 세부 내용은 `### 0-1.`, `### 0-2.`, `### 1-1.` 형식의
  **절**로 나눈다.
- `0장`은 전체 학습 목표와 도구의 역할을 소개한다.
- `1장`부터는 실제 학습 순서에 맞는 카테고리를 사용한다.
- 날짜 문서의 번호는 그날 대화한 순서가 아니라 전체 교과 과정의 논리적 순서를
  따른다.

## 네 단계 교육 구조

각 장은 `장의 학습 목표 → 세부 주제 → 내용 설명 → 예제 또는 실습`의 네 요소를
갖는다. 학습 목표는 절마다 반복하지 않고 장의 시작에서 그 장을 마치면 할 수 있어야
하는 일을 모아 제시한다.

```markdown
## 2. ROS 2 기본 개념과 CLI

### 이 장의 학습 목표

- 이 장을 마친 뒤 설명하거나 수행할 수 있어야 하는 행동을 적는다.

### 2-1. 노드와 토픽

#### 주제

이번 절에서 배우는 내용을 한 문장으로 적는다.

#### 내용 설명

용어의 뜻, 필요한 이유, 작동 원리와 주의점을 쉬운 말로 설명한다.

#### 예제 또는 실습

실행 위치, 명령 또는 코드, 예상 결과와 확인 방법을 적는다.
실행 전이면 `실습 상태: 예정`, 실행했다면 `실습 상태: 완료`라고 표시한다.
```

추가 원칙:

- 학습 목표는 `이해한다`보다 `차이를 말할 수 있다`처럼 확인 가능하게 쓴다.
- 예제 코드는 복사해 실행할 수 있어야 하며 초보자용 주석을 포함한다.
- 예상 출력과 실제 실행 결과를 구분한다.
- 오류 메시지, 원인과 해결 과정도 학습 내용으로 남긴다.
- 같은 개념을 여러 번 대화했다면 하나의 설명과 실습으로 통합한다.
- 터미널 전체 출력 대신 학습 내용을 확인하는 데 필요한 부분만 남긴다.
- 특정 컴퓨터나 Codex 실행 환경에만 해당하는 문제는 일반 ROS 학습과 분리한다.
- 바뀔 수 있는 제품 정보는 공식 문서를 우선하고 출처를 남긴다.
- 마지막에는 완료한 내용과 아직 하지 않은 내용을 구분한다.
