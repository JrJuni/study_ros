# ROS 날짜별 학습자료 갱신

실제 대화와 실습 결과를 로봇 입문 학생용 날짜별 교재로 정리하기.

## 준비

1. 저장소 루트의 `AGENTS.md` 전체 읽기.
2. `docs/README.md` 전체 읽기.
3. 새 문서를 만들거나 구조를 크게 바꿀 때
   `references/lesson-template.md` 전체 읽기.
4. 기존 `docs/lesson_*.md`와 Git 변경사항을 확인해 사용자 내용 보호하기.

## 문서 선택

1. 환경 정보의 Asia/Seoul 날짜를 `YYMMDD`로 변환하기.
2. `docs/lesson_YYMMDD.md`가 있으면 그 파일 갱신하기.
3. 파일이 없으면 템플릿으로 생성하기.
4. 같은 날짜에 `-2`, `_v2` 같은 별도 문서를 만들지 않기.
5. `docs/README.md` 문서 목록 함께 갱신하기.

## 내용 구성

1. 대화에서 실제로 설명한 내용, 실행한 명령, 확인 결과와 결정 사항 추출하기.
2. `docs/README.md`에서 가장 알맞은 카테고리 선택하기.
3. 각 주제를 다음 순서로 작성하기.
   - `### 주제`
   - `### 학습 목표`
   - `### 내용 설명`
   - `### 예제 또는 실습`
4. 목표를 설명할 수 있다, 명령을 실행할 수 있다처럼 확인 가능하게 쓰기.
5. 고등학생이 처음 읽는다고 가정해 용어를 풀고 필요하면 비유 추가하기.
6. 코드에 초보자용 주석, 실행 위치, 예상 결과와 성공 확인 방법 포함하기.
7. 실행 전은 `실습 상태: 예정`, 실행 후는 `실습 상태: 완료`로 구분하기.
8. 오류가 있었다면 오류 문구, 원인과 해결 과정 남기기.

## 정확성

- 대화에서 다루지 않은 내용을 학습 완료로 만들지 않기.
- 변할 수 있는 버전, 지원 환경과 설치법은 공식 ROS 또는 NVIDIA 문서를
  확인하고 출처와 확인 날짜 기록하기.
- 사용자의 운영체제와 하드웨어 확인 전 설치 경로 확정하지 않기.
- 실제 출력과 설명용 예상 출력 명확히 구분하기.
- 기존 문서와 사용자 변경사항을 덮어쓰지 말고 병합하기.

## 완료 확인

1. 파일명이 `lesson_[0-9]{6}.md` 형식이고 실제 날짜인지 확인하기.
2. 모든 주제에 네 필수 부분이 있는지 확인하기.
3. Markdown 링크와 코드 블록이 닫혔는지 확인하기.
4. 문서 목록의 날짜와 링크가 실제 파일과 일치하는지 확인하기.
5. 변경 파일과 추가한 학습 내용을 사용자에게 짧게 보고하기.
